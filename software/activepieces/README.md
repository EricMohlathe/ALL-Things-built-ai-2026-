# Activepieces (self-hosted automation engine)

Upstream: [activepieces/activepieces](https://github.com/activepieces/activepieces)
(AGPL/MIT monorepo, ~300 MB — deployed via the official Docker image rather than
vendored whole, same policy as Remotion/python-aiplatform in `PROVENANCE.md`).

## Run it

```bash
cd software/activepieces
cp .env.example .env        # setup.sh does this and fills the secrets for you
docker compose up -d        # UI + API on http://localhost:8080
```

`docker-compose.yml` and `.env.example` are copied verbatim from the upstream
repo (commit `4991f3be`): app + 5 workers + postgres (pgvector) + redis.
Required secrets in `.env` — `AP_ENCRYPTION_KEY` (32 hex chars),
`AP_JWT_SECRET`, `AP_POSTGRES_PASSWORD` — are auto-generated by `../../setup.sh`.

## Agent OS integration

`ap-bridge.mjs` is a zero-dependency Node CLI that lets Agent OS agents (and
you) drive the instance:

```bash
node ap-bridge.mjs health                       # instance up?
node ap-bridge.mjs flows                        # list flows
node ap-bridge.mjs runs                         # recent executions
node ap-bridge.mjs trigger <flowId> '{"x":1}'   # fire a webhook-triggered flow
node ap-bridge.mjs api GET /api/v1/app-connections
```

Configure with `AP_BASE_URL` (default `http://localhost:8080`) and optional
`AP_API_KEY`. The Agent OS standard describing when/how agents should use this
lives at `agent-os/standards/activepieces-automation.md` and is indexed for the
`/agent-os` commands (`inject-standards`, `index-standards`).

## Hacking on Activepieces itself

The full source is not committed. `setup.sh --with-activepieces-src` shallow-
clones it to `software/activepieces/src/` (git-ignored).
