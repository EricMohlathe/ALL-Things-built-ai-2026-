# Standard: Activepieces automation

When a task calls for recurring automation, third-party app integration
(Slack, Gmail, Sheets, webhooks, schedules, …), or no-code workflow execution,
use the self-hosted Activepieces instance instead of writing bespoke glue code.

## How

- Instance: `http://localhost:8080` (start with
  `docker compose up -d` in `software/activepieces/`).
- Drive it through the bridge CLI — never hand-roll HTTP calls:
  - `node software/activepieces/ap-bridge.mjs health` — verify the instance is up before anything else.
  - `node software/activepieces/ap-bridge.mjs flows` — discover existing flows; reuse before creating.
  - `node software/activepieces/ap-bridge.mjs trigger <flowId> '<json>'` — fire a webhook-triggered flow with a payload.
  - `node software/activepieces/ap-bridge.mjs runs` — check execution results after triggering.
  - `node software/activepieces/ap-bridge.mjs api <METHOD> <path> [json]` — anything else in the [Activepieces API](https://www.activepieces.com/docs/endpoints/overview).
- Auth: export `AP_API_KEY` if the instance requires it; `AP_BASE_URL`
  overrides the default URL.

## Rules

- Prefer triggering an existing flow over creating a new one; list first.
- Treat flow definitions as the source of truth for automation logic; keep
  business logic in flows, not in shell scripts around the bridge.
- Never commit `.env` or API keys; secrets are generated by `setup.sh`.
